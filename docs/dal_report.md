## 1. Цель работы

Реализовать уровень доступа к данным (Data Access Layer) для базы данных спортшколы с использованием PHP и PDO. Все SQL-запросы должны быть инкапсулированы в классах-репозиториях, обеспечена защита от SQL-инъекций через подготовленные выражения, реализованы транзакции для операций, затрагивающих несколько таблиц.

---

## 2. Архитектура уровня доступа к данным

Реализован паттерн Repository. Созданы следующие классы:

**Database** — класс-одиночка (Singleton) для управления подключением к базе данных. В конструкторе создаётся PDO-объект с настройками: режим сообщения об ошибках — исключения, режим выборки по умолчанию — ассоциативный массив, эмуляция подготовленных выражений отключена.

**AbstractRepository** — абстрактный базовый репозиторий с общими методами findAll, findById, delete. Эти методы работают с любой таблицей благодаря параметрам tableName и primaryKey.

**CoachRepository** — репозиторий для работы с тренерами. Добавлены специфические методы: findByPhone (поиск по телефону), getCoachesWithHighFillRate (тренеры с заполняемостью групп более 80 процентов), create (создание нового тренера).

**AthleteRepository** — репозиторий для работы со спортсменами. Добавлены методы: findByParentPhone (поиск по телефону родителя), getRatingByAchievements (рейтинг спортсменов по количеству достижений с использованием оконной функции RANK), create (создание нового спортсмена).

**EnrollmentRepository** — репозиторий для работы с записями на тренировки. Добавлены методы: getEnrollmentsWithDetails (JOIN-запрос с подробной информацией), findByAthleteId (поиск записей по спортсмену), create (создание записи с транзакцией), cancel (отмена записи с транзакцией).

**RepositoryException** — собственный класс исключения для обработки ошибок репозиториев.

---

## 3. Защита от SQL-инъекций

Во всех методах репозиториев используются подготовленные выражения PDO. Пользовательские данные никогда не подставляются в SQL-запрос напрямую через конкатенацию строк. Вместо этого используются плейсхолдеры (именованные :name или вопросительные знаки), а значения передаются через метод execute.

Пример из метода findByPhone класса CoachRepository:

$sql = 'SELECT * FROM coaches WHERE phone = :phone';
$stmt = $this->pdo->prepare($sql);
$stmt->execute([':phone' => $phone]);

Это полностью исключает возможность SQL-инъекций, так как PDO автоматически экранирует значения.

## 4. Транзакции

Транзакции реализованы в двух методах репозитория EnrollmentRepository: create и cancel.

В методе create выполняются две операции: вставка новой записи в таблицу enrollments и увеличение значения current_capacity в таблице sport_groups. Если какая-либо из операций завершается ошибкой или нарушается бизнес-правило (спортсмен уже записан в эту группу), вызывается rollBack и все изменения отменяются.

В методе cancel выполняются: изменение статуса записи на «отчислена» и уменьшение current_capacity в таблице sport_groups. Обе операции обёрнуты в транзакцию.

Пример из метода create:

try {
    $this->pdo->beginTransaction();
    // проверка и вставка
    // обновление вместимости
    $this->pdo->commit();
} catch (PDOException $e) {
    $this->pdo->rollBack();
    throw new RepositoryException('Ошибка при создании записи: ' . $e->getMessage());
}

---

## 5. Обработка ошибок и исключения

Создан собственный класс RepositoryException, наследуемый от Exception. Все методы репозиториев выбрасывают это исключение при ошибках: запись не найдена, нарушение уникальности ключа, ошибка базы данных.

В демонстрационном скрипте demo.php все вызовы методов репозиториев обёрнуты в try-catch. При возникновении ошибки выводится понятное сообщение без раскрытия технических деталей подключения.
